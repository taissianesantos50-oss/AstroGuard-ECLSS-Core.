## 1. Executive Summary

AstroGuard-ECLSS-Core is a research and simulation prototype for long-duration space-mission monitoring. The project combines an environmental ECLSS-oriented simulation with a deterministic human-health monitoring layer and presentation interfaces for telemetry visualization.

The current implementation is organized as an incremental software history:

`v1.3 → v1.4 → v1.5 → v1.6 → v1.7 → v1.8`

The project is intentionally scoped as a prototype. Physiological telemetry is synthetic, visualization-derived stress indices are non-medical metrics, and decision thresholds are software-verification parameters.

The decision engine is kept separate from visualization layers. The v1.5 and v1.6 interfaces consume the telemetry scenario and do not replace or silently modify the v1.4 health-state evaluator.

## 3. v1.4 Human Health Monitoring Layer

### Inputs

- Heart rate (bpm)
- SpO2 (%)
- Body temperature (°C)
- Respiratory rate (breaths/min)
- Fatigue index
- Well-being index

### States

- `NORMAL`
- `ATTENTION`
- `CRITICAL`

The evaluator uses deterministic software thresholds defined in `src/health_monitor.c`. These thresholds exist to exercise prototype state transitions and are not presented as clinical limits.

### Verification scenario

The integrated scenario intentionally exercises:

- time 0–7: NORMAL
- time 8–13: ATTENTION
- time 14–20: CRITICAL

Expected distribution:

- 8 NORMAL frames
- 6 ATTENTION frames
- 7 CRITICAL frames

The existing evaluation report records successful compilation, unit tests, integrated execution and telemetry consistency.

## 4. Telemetry Contract

The combined telemetry schema is:

```text
Time,O2,Pressure,Temp,O2_Valve,Heater,HeartRate,SpO2,BodyTemp,RespRate,Fatigue,WellBeing,HealthStatus
```

The CSV is the common data boundary between the simulation and visualization layers.

## 5. v1.5 Visualization Layer

The Python visualization consumes the telemetry contract and presents:

- mission time
- environmental stress representation
- human-stress representation
- current health state
- environmental telemetry
- human telemetry
- conceptual spacecraft geometry

The environmental and human stress values in this layer are visualization-only derived indices. They are not medical scores and are not used as replacements for the deterministic v1.4 decision engine.

## 6. v1.6 Web Dashboard

The browser dashboard provides:

- mission state
- O2, pressure and temperature
- heart rate, SpO2, respiration and fatigue
- time-series visualization
- alert / decision-support panel
- actuator-state display
- current telemetry packet in JSON form

The dashboard uses embedded demonstration telemetry and requires no external runtime dependency.

## 8. Reproducibility

### C simulation

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic src/health_monitor.c src/astroguard_v1_4.c -I src -o astroguard_v1_4
./astroguard_v1_4
```

### Unit tests

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic src/health_monitor.c tests/test_health_monitor.c -I src -o test_health_monitor
./test_health_monitor
```

Expected test result: `TESTS_PASS`.

### 3D visualization

```bash
python -m pip install -r requirements-v1.5.txt
python src/astroguard_v1_5.py
```

### Web dashboard

Open:

`dashboard/index.html`

No build step is required for the current dashboard implementation.

## 10. Scientific and Safety Boundary

AstroGuard should be described as a **research / simulation prototype**.

Do not describe the synthetic telemetry as astronaut data. Do not describe prototype thresholds as clinical limits. Do not claim medical validation, flight qualification, Artemis validation, NASA certification, or operational spacecraft deployment unless independently documented by an authoritative source.

The project demonstrates software architecture, deterministic state evaluation, telemetry integration and mission-oriented visualization.

## 12. Final Project Statement

AstroGuard connects environmental mission awareness with human-health telemetry in a single software prototype. Its contribution is demonstrated through a reproducible simulation, deterministic state evaluation, telemetry contract, 3D visualization and browser-based mission interface.

The project remains explicitly bounded as research and simulation software rather than a clinical or flight-qualified system.
