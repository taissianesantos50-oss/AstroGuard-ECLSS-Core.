# AstroGuard v1.6 — Web Mission Dashboard

## Purpose
v1.6 converts the verified v1.4 telemetry scenario and the v1.5 visualization concepts into a browser-based mission dashboard.

The dashboard is a **research/demo interface**. It does not diagnose an astronaut, replace clinical systems, or issue flight commands.

## Implemented
- Mission health-state banner: NORMAL, ATTENTION, CRITICAL
- Environmental telemetry: O2, pressure and temperature
- Human telemetry: heart rate, SpO2, respiration and fatigue
- Visualization-only environmental and human stress indices
- Time-series mission chart
- Actuator-state display
- Current telemetry packet in JSON form
- Automatic playback of the synthetic v1.4 scenario
- Responsive layout
- Explicit SIMULATION · RESEARCH PROTOTYPE boundary

## Data contract
The dashboard preserves the v1.4 telemetry semantics:
Time, O2, Pressure, Temp, O2_Valve, Heater, HeartRate, SpO2, BodyTemp, RespRate, Fatigue, WellBeing, HealthStatus

The browser copy of the demonstration data is embedded in dashboard/app.js so the interface can be opened locally without a web server or cross-origin CSV fetch.

## Architecture
v1.4 C simulation -> verified telemetry scenario -> v1.5 Python 3D visualization and v1.6 Web mission dashboard.

The v1.6 interface is read-only with respect to the telemetry model. It presents state and decision-support information but does not independently evaluate medical conditions.

## Run locally
Open dashboard/index.html in a modern browser. No build step is required.

## Verification scenario
The embedded scenario contains 21 frames:
- t=0–7 s: NORMAL
- t=8–13 s: ATTENTION
- t=14–20 s: CRITICAL

This mirrors the verified v1.4 integrated scenario.

## Scientific and engineering boundary
The stress indices are normalized visualization metrics, not validated medical scores. Human telemetry values are synthetic. Thresholds are prototype rules and should not be interpreted as clinical limits or flight certification criteria.
